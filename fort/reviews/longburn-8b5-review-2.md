## New findings (all follow-up beads; none blocking)

11. **`eslint.config.mjs:23-49` — should-fix.** The widened ban enumerates `Date` and `performance` but not the rest of the class. Probed clean in `src/sim/`: `crypto.randomUUID()`, `crypto.getRandomValues(...)`, `process.hrtime.bigint()`, `Temporal.Now.instant()`, and `import * as p from "node:perf_hooks"; p.performance.now()`. `crypto.*` is the one that matters: generating an entity or order ID is the single most likely way unseeded randomness enters a sim, and it is exactly the reach a developer makes without thinking. Two more selectors close it. (Aliasing forms — `const D = Date; D.now()`, `globalThis["Date"]` — also pass, but those are deliberate evasion, which no lint rule can stop and which I do not count against this work.)
12. **`test/determinism-lint.test.ts:12` — should-fix.** The assertion is `result.errorCount === 6`: a bare count, not which guards fired. Proved fungible — I removed the `performance` selector and added an unrelated `ArrayExpression` selector that fires once on the fixture; the count stayed 6, the test stayed green, and `performance.now()` in `src/sim/` went from 1 error to 0. Assert on rule IDs and lines (or per-message) instead. Secondary cost of the bare count: adding a *stronger* guard that fires on the fixture also turns the test red, which quietly penalizes fixing finding 11.
13. **`package.json:8` + `eslint.config.mjs:8` — nit.** The fixture is inside the config's `files` glob but outside the lint script's (`eslint src`), so `npx eslint .` fails by construction with the fixture's 6 errors. Verified. Broadening the lint script — a natural future improvement — permanently reddens `verify`. Add an `ignores` entry for the fixture in the shared config and have the test supply the rules via `overrideConfig`, or move the fixture outside the default glob.
14. **`tsconfig.json:14` — nit.** `include` is `src/**/*.ts` only; `tsc --listFiles` sees zero files under `test/`. The two new TypeScript files (`determinism-lint.test.ts`, the fixture) are never type-checked by `npm run build`. Small surface today, but `verify`'s type gate no longer covers all TypeScript in the repo.
15. **`fort/handoffs/forge-2026-08-03-completion.md:14-17` — nit (process).** The clarification was inserted mid-file rather than at the end, so a pre-existing "Verified facts" bullet (`npm run verify passed ... 3 tests across 2 files`) now sits *under* the "Clarification appended 2026-08-04" heading. Nothing was falsified and nothing was deleted, but the placement re-dates a 2026-08-03 claim into a 2026-08-04 section, and that claim is now stale (7 tests across 4 files). Append at the end of the file; never into an existing section.
16. **`src/sim/clock.ts:24-31` — nit.** `SimClock.testing()` is now byte-identical to `SimClock.production()`, and `clock.test.ts:12` ("lets tests advance virtual time independently of wall time") proves nothing the production test does not.
